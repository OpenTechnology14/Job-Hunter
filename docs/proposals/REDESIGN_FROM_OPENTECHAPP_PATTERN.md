# Proposal: Redesign Job Hunter's docs and visual layer from the OpenTechnologyApp pattern

**Status:** Proposed
**Date:** 2026-10-22
**Release profile:** Local single-user (nothing here depends on hosted mode; see §5)
**Evidence:** Verified for every Job Hunter row. The reference rows are Verified by reading
file trees and files on each repository's `main`: OpenTechnologyApp `d2467d8`, MyFeed
`a7eaf28`, Hybrid_Creator_Platform `54266fc`. Job Hunter was read at `29df0c9`.
Recommendations are Proposed.

> **Public-repo note.** Job Hunter is public. OpenTechnologyApp, MyFeed and the

## 1. Executive summary

OpenTechnologyApp ("the App") is the ecosystem's design template of record. MyFeed copies
its **agent and documentation layer** closely. Its **visual layer** is only a loose copy:
MyFeed uses a different typeface and different token names. So "match the App" means two
separate things, and this audit grades them separately.

**Top line: 29 patterns compared. 7 Match, 10 Partial, 10 Missing, 2 N/A.**

- **Agent layer:** close to parity. The four skills, the build-prompting digest, the
  evidence labels, the proposal SOP and the audit matrix all match. These landed in PR #2.
- **Docs layer:** where most of the gaps are. Job Hunter has no `docs/readable/` split, no
  generated agent registries, no ordered proposal queue with stable IDs, and no pointer to
  the design-system hub.
- **Visual layer:** Job Hunter has its own small token set on `:root`, but only a dark
  theme. White text on its accent buttons measures **3.18:1**, which fails WCAG AA for
  normal text.
- **Marketing layer:** absent. MyFeed (the mirror) has no `MARKETING.md` either, so this is
  an App-specific pattern. Whether Job Hunter has one is an owner call (D05).

One finding changes the priorities. The App's `job_hunter` project template is designed to
**replace** Job Hunter's Flask admin UI as the review surface (the App's template crosswalk
and its Job Hunter gap proposals). Visual work on the Flask admin may therefore be short-lived.
Gate D01 decides that before any restyle beyond the accessibility fix.

**Correction to the brief:** Job Hunter has **no Flask templates.** The admin is one static
`admin/static/index.html` with inline CSS and JS. It also has **no PDF generator on public
`main`.** `generate_resumes.py` was removed in the history rewrite that scrubbed personal
data. `fpdf2` is still in `requirements.txt`, and `APP_PLAYBOOK.md` and `MAINTENANCE.md` §7
still describe the generator, so the docs have drifted. Resumes are user-supplied PDFs. The
only HTML output to style is therefore the admin page.

## 4. Gaps worth leaving

- React / shadcn component conventions and Storybook: there's no component layer, and "no build step" is a locked decision.
- Tailwind config and the shadcn HSL variable names: no Tailwind; the hub's role names are the bridge if they're ever adopted (row 12 above).
- Web-font import (MyFeed's pattern): the App uses a system stack, as Job Hunter does; the typeface question belongs to hub decision D-3.
- `proposal-registry.json` plus an `audit:proposals` CI gate: there's no CI, and a single queue doc is enough at this scale.
- Review-note companions and Revisit & Review bookkeeping: an App-specific process for a large queue.
- Operator-action handoff section: no owner-operated deployment pipeline exists to hand off.
- Proposal dashboard HTML snapshot: a convenience for 35-item queues; Job Hunter has 4 proposals.
- Click matrix plus an E2E session guard: the admin is one page, and the `TESTING.md` §5 tables cover it.
- Connection matrix: MyFeed's domain (feed connections); there's no equivalent concept here.
- Token-driven PDF styling: no PDF generator on public `main`.
- `.claude/commands/` (audit, pre-merge, …): App-only; the mirror doesn't carry them.
- C++ / data-table parity in the style of Ironfall's P-009: Ironfall-specific, with no Job Hunter analogue.

## 5. Scope boundaries

- **JH-D01 (hosted / deployed mode) is OPEN. Nothing here depends on it.** No item adds
  auth, theming per tenant, hosted copy, or wording that implies `--deployed` is production-ready.
  The copy pass (item 11) must keep the existing "local, single-user" release statement.
- **The supervision boundary is unchanged.** No design item touches the submit path,
  `browser_apply.py`, or confirmation copy semantics. Restyling the apply-related UI labels is
  string-only, and keeps the explicit-confirmation meaning.
- **Hub adoption rule.** The hub's tokens are `drafted`, not approved. Job Hunter keeps its own values until a
  hub token is approved. Items 1 and 2 record local values and a local override; they do not
  adopt hub values.
- **Public / private boundary.** No item copies private content (marketing claims, token values, internal
  proposal text) into this public repo. A pointer may name private files; it may not quote them.
- **Inbound links.** The App's template crosswalk links to this repo's root `APP_PLAYBOOK.md`
  and `CLAUDE.md`, and to `docs/ADMIN_PANEL.md`, `docs/USER_GUIDE.md` and `docs/GAP_AUDIT.md`.
  Any move under item 9 must leave forwarding stubs at the old paths, or update that crosswalk
  in the same change.
- **GitHub community files stay at the root:** `README.md`, `LICENSE`, `CONTRIBUTING.md`,
  `SECURITY.md`, `CODE_OF_CONDUCT.md`. GitHub only surfaces them there.
- **Not in scope:** CI itself (`JH-001`), the App-side `job_hunter` template (which the App's own
  queue owns), and any change to matching, scraping or storage behavior.

## 9. Rollout and rollback

Phase 1 is items 1–5, in one PR with no decisions needed. Phase 2 follows D02–D04 and D07.
Phase 3 follows D01, D05, D06 and the relevant hub approvals. Every item is docs or CSS
only, so rollback is a revert. A `docs/readable/` move (item 9) leaves stubs, so a revert never
breaks inbound links.

## 10. Risks and unresolved decisions

- **Restyle waste.** If the App's template replaces the Flask admin, visual work beyond item 2 is
  throwaway. D01 exists to prevent that.
- **Hub drift.** The hub merged on 2026-10-22 and is still drafted. A pointer written now cites a
  moving target. The pointer records the hub revision it was checked against, so a stale revision is
  the signal to re-check.
- **The mirror is stale too.** MyFeed's pointer still says the hub is not published. That isn't
  Job Hunter's to fix, but it means "mirror MyFeed" can't mean copying it word for word.
